# CareTip — SEO Canonical / Initial HTML Implementation Report

**Date:** 2026-09-27  
**Related audit:** `CARETIP_SEO_CANONICAL_FORENSIC_AUDIT.md`

---

## 1. Root cause confirmed

Every public URL was served the same Vite `index.html` shell with **homepage** `<title>`, `meta description`, `link rel="canonical"`, `og:url`, and `#caretip-static-summary` content. Route-specific metadata was applied only after React hydration via `CareTipRouteSeo` → `useEffect` / `applyDocumentSeo()`. Crawlers and Google Search Console could therefore record **user-declared canonical `https://caretip.de/`** for deep URLs such as `/pricing`.

---

## 2. Architecture selected

**Build-time static HTML generation (post-Vite prerender)** for all paths in `SITEMAP_PATHS` / `CARETIP_SITEMAP_PATHS`.

After `vite build`, `scripts/prerender-public-seo-html.ts`:

1. Reads `dist/index.html` as the SPA shell template.
2. For each indexable sitemap path, calls **`resolveRouteSeo()`** (same source of truth as the client).
3. Applies **`injectRouteSeoIntoHtml()`** to patch head tags, JSON-LD, and `#caretip-static-summary`.
4. Writes:
   - `/` → `dist/index.html`
   - `/pricing` → `dist/pricing/index.html`
   - `/industries/hotels` → `dist/industries/hotels/index.html`
   - etc.

**Vercel / static hosts:** Existing filesystem entries are served **before** SPA fallback rewrites (`vercel.json`, `public/_redirects`), so crawlers receive route-specific HTML without SSR for the authenticated app.

---

## 3. Why this approach

| Criterion | Decision |
|-----------|----------|
| No full-app SSR | Authenticated/dashboard/tip flows unchanged — only extra HTML files under `dist/`. |
| Single SEO source of truth | Reuses `resolveRouteSeo()`, `matchSeoRoute()`, `buildJsonLdForRoute()` — not a parallel copy/paste map. |
| Fits Vite + Vercel | No Next.js migration; minimal change to `npm run build`. |
| i18n | Initial HTML uses **German** bundles (same default as root `index.html` `lang="de"`). Client navigation still updates EN via existing i18n + `CareTipRouteSeo`. |
| Risk | Low: dev `index.html` unchanged; production `dist/` enriched at build time. |

SSR, edge middleware injection, and full React SSR were **not** introduced.

## 9. `/how-it-works` resolution

**Product decision:** No standalone indexable page; content lives on `/` (`#how-it-works`) and industry pages.

**Implemented:**

- Removed from `SITEMAP_PATHS`, `CARETIP_SITEMAP_PATHS`, and `INDEXABLE_EXACT`.
- `matchSeoRoute('/how-it-works')` → **not indexable** (`notFound`).
- Router: redirect to `/#how-it-works`.
- Internal marketing links updated from `/how-it-works` to `/#how-it-works`.
- E2E Calendly test updated.

**Not done:** No new standalone How It Works page.

**Note:** `/how-it-works` is **not** prerendered; requests fall through to generic `index.html` until client redirect. Acceptable because URL is **not** in sitemap and is **noindex** when SEO runs.

- **`/how-it-works`:** Legacy URL relies on client redirect; not in sitemap.
- **Google canonical:** Correct initial HTML is necessary but **not sufficient** to force Google-selected canonical — monitor GSC after deploy.
